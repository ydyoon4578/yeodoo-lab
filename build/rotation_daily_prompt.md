# 전략 탐색 풀 일일 갱신 — 헤드리스 작업 지시서

이 문서는 `build/rotation_daily.ps1` 이 `claude -p` 로 그대로 먹이는 프롬프트다.
사람이 읽으라고 쓴 것이 아니라 **매일 아침 무인으로 실행되는 지시**다.

너는 지금 `C:\Users\USER\yeodoo-lab` 에서 돌고 있다. `data/rotation_pool.json` 은
공개 사이트 `rotation.html`(여두 · 오늘의 전략 탐색)이 읽는 유일한 자료다.
카드 하나가 전략 하나이고, 화면은 날짜 시드로 매일 10선을 뽑아 보여 준다.

## 🚨 절대 규칙 — 어기면 그날 작업을 통째로 버리는 편이 낫다

1. **고칠 파일은 `data/rotation_pool.json` 하나뿐이다.** 다른 파일을 고치면 러너가
   푸시를 거부한다(그 검사가 실제로 걸려 있다).
2. **커밋·푸시하지 마라.** 러너가 검증을 통과시킨 뒤에 직접 한다.
3. **출처 URL 을 지어내지 마라.** 반드시 WebSearch/WebFetch 로 실제로 연 것만 적는다.
   못 찾았으면 그 카드는 "이번 주기에 새로 확인된 것이 없다"고 적는 것이 맞다.
   지어낸 URL 하나가 이 사이트 전체의 신뢰를 없앤다.
4. **`**` 같은 마크다운을 쓰지 마라.** 이 필드들은 `esc()` 로 렌더돼 기호가 그대로 찍힌다.
   강조가 필요하면 `🚨` 와 `⚠` 를 쓴다(기존 카드들이 그렇게 쓰고 있다).
5. **JSON 모양을 바꾸지 마라.** `json.dumps(..., ensure_ascii=False, indent=1)` + 끝에 개행.
   기존 카드의 필드 순서·다른 필드 값은 건드리지 않는다.

## 순서 — 이 순서가 핵심이다

🚨 **신규 카드를 먼저 넣고 그 다음에 10선을 뽑는다.**
`rotation_select.py` 의 `pick()` 은 풀 전체를 셔플하므로 카드를 하나만 더해도 10선이
통째로 달라진다. 종전에는 뽑고 → 갱신하고 → 추가하는 순서였고, 그래서
**2026-08-07 에는 그날 화면에 뜬 10선 중 8종이 갱신 대상이 아니었다.**
갱신을 하고도 방문자는 옛 카드를 봤다. 같은 실수를 반복하지 마라.

### ① 신규 전략 카드 1종을 먼저 추가한다

웹 리서치로 이 풀에 **아직 없는** 전략을 하나 찾아 카드로 만든다.
먼저 기존 101종의 `id`·`name` 을 전부 읽어 중복을 피하라 — 이름만 다르고 같은 축인 것도 중복이다.

- `id`: 카테고리 접두어 + 그 카테고리의 다음 번호(A/B/C/D/E). 최상위 `id_moved` 에 적힌
  id 는 예전에 옮겨간 것이라 **재사용 금지**다.
- 필수 필드: `id · cat · cat_label · name · type · target · purpose · principle · entry ·
  performance · recent · recent_at · sources`. 하나라도 빠지면 검증이 막는다.
- `sources` 는 최소 2건. 가능하면 원논문(저자·연도·저널·권·호·페이지)을 포함한다.
- `recent` 에는 "오늘 신규 등록"이라고 적고, **이 랩에서 잴 때의 제약을 미리 적어라** —
  유니버스가 S&P 500 ∪ NASDAQ 100 대형주 518종이라 소형·저커버리지 구간이 빠진다든가,
  이미 있는 어느 카드와 축이 겹쳐 증분을 물어야 한다든가.
- ⚠ 새로 넣을 만한 것이 정말 없는 날은 **넣지 않아도 된다.** 억지로 채우면 풀이
  비슷한 카드로 불어난다. 안 넣었으면 아래 ③에서 그 사실을 적어라.

### ② 오늘의 갱신 대상을 뽑는다

```
python build/rotation_select.py
```

`KST_DATE` 아래 10줄이 오늘의 10선, `STALE3` 아래 3줄이 가장 오래 방치된 3종이다.
합쳐서 13종이 오늘의 대상이다(신규 카드가 10선에 뽑혔으면 그만큼 겹친다).

### ③ 13종의 `recent` 를 다시 쓴다

카드마다 WebSearch 로 **그 전략에 관한 최근 동향**을 찾아 `recent` 를 새로 쓰고
`recent_at` 을 오늘(KST) 날짜로 바꾼다. 최상위 `generated` 도 오늘로 바꾼다.

무엇을 쓰나:
- 새 논문·정식 게재·서지 확정(저널·권·연도·페이지까지)
- 그 전략이 사는 시장의 최근 실측(수익률·스프레드·밸류에이션·집계 통계)
- **반론과 감쇠 증거**. 이 풀은 아이디어 목록이지 추천 목록이 아니다.
  좋은 소식만 적힌 카드는 이 사이트의 목적에 반한다.
- 그 전략을 이 랩에서 재려 할 때 걸릴 제약(자료 부재·유니버스 불일치·후보 풀 두께)

어떻게 쓰나:
- 기존 `recent` 를 통째로 대체하되, 여전히 유효한 사실은 남긴다. 매일 처음부터 쓰지 마라.
- 새로 확인된 것이 정말 없으면 **그렇게 적어라.** 없는 소식을 지어내는 것보다 낫다.
- 수치를 적을 때는 출처를 문장 안에 밝힌다(예: "FactSet 2026-07", "VanEck 2026").
- 랩이 이미 이 전략을 검정했다면(`lab` 필드가 있는 카드) 그 판정과 모순되게 쓰지 마라.

### ④ 스스로 확인한다

```
python build/rotation_select.py
```

마지막 줄이 **`FRESH_OK`** 여야 한다. `NOTFRESH` 면 화면에 뜰 10선 중 갱신 안 된 것이
있다는 뜻이고, 십중팔구 ①을 ③ 뒤에 한 것이다. 그 카드들을 마저 갱신하고 다시 확인하라.

```
python build/validate_site.py
```

마지막 줄이 **`사이트 검증: 통과 ✅`** 여야 한다. 실패하면 사유를 읽고 고쳐라 —
대부분 마크다운 기호(`**`)나 필수 필드 누락이다.

### ⑤ 끝나면 한 줄로 보고한다

마지막 출력에 이 형식으로 한 줄을 적어라(러너가 커밋 메시지에 쓴다):

```
DONE 최근동향 <N>종 갱신 + 신규 <0 또는 1>종(<id> <이름>)
```

신규를 안 넣은 날은 `+ 신규 0종(사유: …)` 으로 적는다.
