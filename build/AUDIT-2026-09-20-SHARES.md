# 감사 — 주식수에 100만 배 단위 사고가 있다 (SHARES) · 2026-09-20

**이 감사는 어제 내가 만든 모든 「시총가중」 수치를 정정한다.**

---

## 1. 어떻게 찾았나 — 의심한 것은 통계가 아니라 자릿수였다

우량성장 30 의 초과수익을 **Brinson 분해**(섹터 배분 vs 종목 선택)하려고
「그 달 편입명단 시총가중」 지수를 재구성했다. 분해 합계가 **연 +3.40%p** 로 나왔는데
확정 잣대는 **+8.16%p** 다. **절반이 안 맞았다.**

검산했더니 —

> **내가 재구성한 지수가 공식 ^GSPC 보다 월 +0.590% (연 +7.08%p) 높다.**

벤치마크가 공식 지수를 7%p 이기면 그 위에 세운 분해는 못 쓴다. 원인을 팠다.

**2026-06 재구성 지수의 비중 상위를 찍었다.**

```
WAT     29.53%     ← Waters Corp. 시총 200억$ 대 회사다
NVDA     4.67%
GOOGL    4.21%
AAPL     4.08%
```

**한 줄로 드러났다.**

## 2. 무엇이 틀렸나

`data/fx/WAT.json` 의 희석 가중평균 주식수(`sh`):

| 분기 | 값 |
|---|---|
| 2025-09-30 | 59.62 |
| 2025-12-31 | **59.76** |
| 2026-04-04 | **98,204.00** |
| 2026-07-04 | 98,204.00 |

**1,643배 튄다.** 같은 시점 기말 발행주식수(`sho`)는 **98.22** 로 정상이다
(Waters–BD 합병으로 59.55 → 98.22 로 늘어난 것이 진짜 변화다).

**즉 회사가 어느 분기에 단위를 바꿔 보고했고(주 ↔ 천주), `refresh_facts.py` 의
단위 판정이 그것을 분기마다 다르게 처리했다.**

## 3. 전수 검사 — WAT 하나가 아니다

`build/audit_shares.py` · 518개사

| | 건수 | 종목 |
|---|---|---|
| **시계열 안에서 10배 넘게 튐** | **238건** | **78종** |
| **같은 시점 `sh` ↔ `sho` 자릿수 불일치(10배↑)** | **136건** | **47종** |

**걸린 종목에 AAPL · AMZN · AVGO · GILD · CB · PCG · FITB 가 들어 있다.**
차이는 대부분 **정확히 100만 배**다.

```
PCG  sho  2012-12-31      430.72  →  2013-03-31  441,509,054.00   (1,025,049배)
FITB sho  2010-09-30  796,283,198.00  →  2010-12-31    796.27     (1,000,017배)
```

**방향이 양쪽 다 있다** — 어떤 분기는 백만으로 나눴고 어떤 분기는 안 나눴다.

## 4. 고친 방법 — 읽는 쪽에서 막는다

`build/shares_clean.py`

> 회사마다 **중앙값을 기준으로 자릿수만 맞춘다.** 관측이 중앙값의 100배를 넘으면
> 1e6 으로 나누고, 1/100 아래면 1e6 을 곱한다. **옮기고도 멀면 버린다.**
> **값을 지어내지 않는다.**

| | 10배 넘게 튀는 관측 |
|---|---|
| 고치기 전 | **149건** |
| 고친 뒤 | **32건** |

**확인** — 2026-08 시총 비중 상위: NVDA 7.16% · AAPL 6.19% · GOOGL 5.54% · MSFT 5.03%.
**자릿수가 맞는다.**

🚨 **근본 수리는 `refresh_facts.py` 의 단위 판정이다. 여기서는 안 한다** —
그쪽을 고치면 `data/fx` 518개를 다시 구워야 하고 그것은 **게시 산출물**이다.
(오늘 `tech_backtest.py` 를 같은 사유로 중단했다.)

## 7. 이 감사가 남기는 규약

1. **시총을 만드는 코드는 `shares_clean.cap_frame` 을 쓴다.** 직접 만들지 않는다.
2. **새 시총가중 결과를 내면 비중 상위 10을 눈으로 본다.** 자릿수가 틀리면 거기서 드러난다.
3. **분해가 안 맞으면 그것이 신호다.** 이 감사는 «Brinson 합계가 확정 잣대와 절반이 다르다»
   에서 시작했다. **맞지 않는 합을 반올림 차이로 넘기지 않는다.**
4. ⚠ **`data/fx` 에 아직 32건의 점프가 남아 있다**(고친 뒤). 그 종목들은
   중앙값 기준 100배 규칙으로도 안 잡히는 것이라 **진짜 변화일 수도 있다.**
   시총을 쓰는 새 작업은 `_audit_shares.json` 의 목록을 먼저 본다.
